Wi-Fi heart-rate logger: Pico W to cloud to inbox

A Raspberry Pi Pico W that logs heart-rate readings to a cloud database, sends every third batch to a language model for a short assessment, and emails the result. I built it up in six versions, adding one networked service at a time.

Overview

This project is about how a microcontroller talks to internet services, built end to end rather than as an isolated demo. The Pico W reads a heart rate every 5 seconds, writes it to a cloud table, asks an AI model for a quick read on the last three values, and emails a report.

Scope note: the heart-rate input is simulated (a random 60–100 BPM reading) so I could build and test the networking pipeline before choosing a sensor. The AI output is a demonstration of chaining services together. It isn't medical advice.

Six versions, one feature at a time

Each version adds one capability on top of a version that already worked. That made every failure easy to locate.

Step through the versions

    Key code

    The main loop barely changed from v3 to v6. New features plugged in behind the same function calls:

    bpm_history = []
reading_count = 0

while True:
    bpm = get_heart_rate()                # simulated for now
    send_to_airtable(bpm)

    bpm_history.append(bpm)
    if len(bpm_history) > HEALTH_EVERY:  # keep the last 3
        bpm_history.pop(0)

    reading_count += 1
    if reading_count % HEALTH_EVERY == 0:
        check_health(bpm_history)         # AI assessment → email

    time.sleep(SEND_INTERVAL)            # 5 s

    The final email step, using umail (trimmed):

    def send_gmail(subject, body):
    smtp = umail.SMTP('smtp.gmail.com', 465, ssl=True)

    What I learned

    • Build in layers. Because each version worked before the next one started, every bug was in the newest few lines.
    • Hand-rolled first, library second. The hand-written SMTP in v5 shows exactly what the library in v6 does underneath.
    • Don't trust API response shapes. The model didn't return what the documentation implied. Defensive parsing with fallbacks kept the loop running.
    • Secrets don't belong in source code. Every version had credentials typed straight into the scripts. They're now placeholders, and the next step is a separate secrets file that stays out of version control.

    Next steps

    1. Replace the simulated input with a real pulse sensor (e.g. a MAX30102 over I²C).
    2. Sync the Pico's clock over NTP so logged timestamps are real wall-clock time.
    3. Batch the cloud writes and only email when a reading falls outside a set range, not every third reading.
